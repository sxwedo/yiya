大概知道能干什么就很好了，加深理解

Claude Code ：

1./btw
适合临时插问。主任务跑着的时候，你突然想补问一个小问题，就用这个，不容易把当前节奏打乱。

2./rewind
回退神器。写偏了、改炸了、实验方案不满意，直接退回去重来。敢试错，才是真效率。

3./model opusplan
这个很关键。强模型负责规划和思考，快模型负责执行和落地。该深的时候深，该快的时候快。

4./simplify
代码能跑，不代表代码干净。这个命令更适合拿来做整理、减冗余、顺结构。

5./fork
一条思路先留着，再开一条新分支试别的方案。做架构、比实现、跑不同路线的时候很好用。

6./remote-control
跨设备续接任务很好用。你不一定非得守着当前这台电脑，当前会话可以接着走。

7.Shift + Tab
切模式很方便。执行、规划这些状态随手切，不用一直重新组织流程。

8.Option + P / Alt + P
快速切模型，不用清空当前输入。写到一半突然想换脑子，这个很省时间。

Codex：

1./model
切模型。复杂任务上强模型，简单任务上轻模型，别让所有活都走同一套配置。

2./permissions
这个很重要。Codex 能读文件、改文件、跑命令，所以权限边界一定要控好。你给多大权限，它就能干多大事。

3./compact
长会话必备。上下文越来越长的时候，压缩一下，保留重点，后面继续干活会轻很多。

4./fork
当前路线保留，再分一条新线去试别的修法。做方案对比时非常顺手。

5./review
提交前很好用。不是让它重写，而是让它从 code review 角度帮你查风险、找问题、补盲区。

6./diff
直接看改了什么。别靠脑子回忆，直接看差异，最稳。

7./agent
适合多 agent 线程场景。不同线程各干各的，你随时切过去继续推进。

8./fast
小任务提速很好用。不需要重推理的时候，直接加快节奏，推进感会强很多。

9.@文件
直接把文件拉进上下文。比你手动描述文件路径高效太多。

10.!命令
直接跑本地 shell。对真正写代码的人来说，这类能力比“多会说两句”更重要。

11.Enter / Tab / Esc
这组快捷逻辑很值钱。执行时还能插指令、排下一步、回上一轮继续分叉，整个交互更像你在实时驾驶 agent。

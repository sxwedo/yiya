01

上篇回顾

上篇完成了 A → B → C → D 的「降维」：从业务需求出发，先厘清分析需求，再确定数据需求与查询逻辑，最后执行查询并验证结果，把一句模糊的业务问题变成一组经过体检、值得信任的数字。

接下来沿着原路「升维」：D 数字结果 → C 数据解读 → B 分析判断 → A 业务结论。数字本身从来不是答案，数字放回分析框架里得出的判断才是答案。

第四步：【D 数字结果 → C 数据解读】描述事实，产出数据解读，并识别重点

### 4.1 难点是什么？ ###

一屏数字，大部分是噪音。AI 最容易犯的毛病，就是从头到尾把每个数念一遍：收入 xx 亿，曝光 xx亿，CVR xx%……

念完，听的人还是不知道今天到底发生了什么。

老练的分析师就不一样，拿到数据的第一个动作是做减法，从几十个数里划掉绝大多数，只留三五个真正值得说的。挑得准不准，这一点也是分析师之间的能力划分重点。能找到问题的关键是哪，是一个很难复制的能力，这个本事很难教，也很难复制。

### 4.2 人怎么做到的？ ###

为什么分析师不会把数字念一遍？

靠专业的统计学方法，与这些年攒下来的手感。要是美食 GMV 掉了 2%，他心里就会报警咯噔一下。

另外，光说 2% 没用，得说清楚它是高了还是低了、离目标差多少。孤零零的数字是不会说话的。我们想让 Agent 学会的就是这两下子：**先做减法，再配参照**。

### 4.3 Agent 该怎么做？ ###

识别异动的方法，其实一点都不缺。这些年各种数据工具里攒下的算法很多，从最基础的同比环比，到复杂的统计检验，应有尽有。

我的想法是把通用的方法 + 具体业务定制的分析思路，一件件包装起来，每件都写清楚它能判什么、什么时候能用，然后交给 AI 自己挑。这里我特意选了让 AI 自主决定，而不是提前写死规则：AI 读了知识库里的业务背景，再结合手上这道题的判断，自己选方法。AI 在纯数理这块的底子相当扎实。当然，这只是我的一个判断与试验，各位可以根据自己的场景决定。

### 4.4 Agent 需要建设什么？ ###

维护好每件武器的信息，都标好：①作用（判什么）+ ②射程（适用边界）+ ③实战（举例）。AI 读懂战场后（任务目标 × 指标类型 × 数据形态 × 样本 × 可解释性），从库里取用趁手的一件或几件。就如同士兵先看清楚眼前是什么仗，指标是什么类型、数据长什么样、样本够不够，再决定抄起哪一件，或者哪几件。

绝大多数时候用不着那些花哨算法。Class 0～2 日常分析，最基础的那几档就够了，真正天天上手、最顺的，往往是那口不起眼的万能平底锅。

注意：大多数固化报告场景，建议稳定写死对应的判断方式，不需要自由探索。

### 4.5 产出目标 ###

这一步交出的是一组有基准、分了主次的事实，不再是一屏平铺的数字，而是哪几个值得关注、各自异常到什么程度。

很多 AI 数据播报读起来像流水账，它把每个数字念了一遍，找不到问题的重点。会念数字的是复读机，**会挑重点、给基准才是分析师**。

第五步：【C 数据解读 → B 分析判断】产出有假设、有方法、有概念的分析判断

### 5.1 难点是什么？ ###

前面找到了异动，这一步要回答它为什么好、为什么不好、原因到底在哪，也就是归因。这是整条链里 AI 最容易骗人的一步。

从「哪个数有问题」到「为什么有问题」，中间隔着一道大坎。看起来有道理，和经得起追问，根本是两回事。Agent 最爱顺口来一句：「是竞对补贴了吧。」听着挺像那么回事，其实一点证据没有。归因一旦开始胡说，第四步辛辛苦苦挑出来的信号就全废了。

### 5.2 人怎么做到的？ ###

老练的人做归因，手上有两把功夫。

第一把：横向比 + 往下钻。

>
>
> 「看到美食收入涨了：是新签在涨还是续签在涨，是连锁大商户还是街边单店，哪个城市、哪个渠道涨得最凶。只说一句美食涨了，跟没说一样。」
>
>

第二把：排除混淆。一看美食收入这周暴涨，新手就乐了：「活动有效果啦？」

>
>
> 「经验丰富的分析师会皱个眉😧：多半是月末商户集中入驻，加上品牌广告打款周期赶在月末冲收，不一定是真有效果了。得先把这种赶节奏的水挤掉，剔干净之后，看看变化到底涨没涨。」
>
>

人还会追问：这段时间到底发生了什么。

* 先看 时间和基数 ：是不是撞上了聚餐旺季或者节假日，去年同期本身是不是就低。同样涨 15%，摊上旺季和淡季，意义完全两样。

* 再看 自己人干了什么 ：美食上了新补贴吗？推荐算法把美食的权重调高？搞美食专场活动？产品是不是改版？

* 最后看外面 ：竞品是不是收了美食的投放，有没有政策或天气帮忙，比如一场冷空气把火锅店带火了？

说到底，靠的是脑子里常年攒下的两样东西：一张这门生意到底怎么赚钱的账本，和一份公司内外这阵子发生过什么的记性。他心里大概就有数：该往哪儿钻，哪些得先排掉。

### 5.3 Agent 该怎么做到有分析判断？ ###

把人的功夫拆成两种可执行模式。

可以拆成两种干法。碰到能慢慢来的异步场景，就让 Agent 转起来：提一个假设，取数去验，排掉混淆，留下证据，不行再换一个，一圈圈逼近那个站得住的原因。碰到即时问答，别搞这么重，直接调指标关系、拆公式、按维度算贡献，先把大头找出来就够了。

* 异步场景 → 假设-验证循环 ：提假设 → 取数验证 → 排除混淆 → 留证据 → 再迭代，直到找到站得住追问的因果，适合深度 归因 。分析本身就是一个发散到收敛的过程。

* 即时问答 → 常规套路：引用 指标关系 → 公式拆解 → 维度贡献分解 ，快速定位大头即可。

### 5.4 Agent 需要建设什么？ ###

AI 分析最被诟病的一点，就是不懂业务。业务方：「不是这么拆的，我们不这么看数。」所以第一件事，是把业务沉淀下来的方法论、指标公式、指标关系图变成 AI 可读取的，让它按业务的路子拆解。

补知识（Context · 脑子里有货）

* 分析方法库： 往下钻、拆公式，把波动拆成三类模型：加法（构成求和）、乘法（链路连乘）、除法（比率结构），再用差分法、LMDI 对数分解、综合贡献法算清每个因子的贡献度。这部分 Agent 现在已经做得不赖。

* 内外部事件： 一个结果的变化只是表象，往往是很多因素导致的。 数据证据与统计方法 ，能把一部分因果证据链讲清楚，但不够。 真实世界 里的很多变化，节日、社会活动、舆情、竞品动作、天气、突发事件，同样在推着数据走。

Agent 能联网搜，可每次搜的结果都不稳定，没法当分析证据用。于是我们搭了一套外部事件采集系统，专门收这些外部情况：采集 → 清洗 → 置信度校验 → 抽象归档 → 沉淀进外部信息库，供分析随时调用。

再就是内部信息，真正难的就在这里。「这段时间到底发生了什么」，其实也困扰着人类分析师们，难在两处：

![](https://mmbiz.qpic.cn/sz_mmbiz/kN3t5R6pdz7ZYlWugP60iaXibKibQjwqG0Q7ZelzLoOIUbEW4euI06yN8qTRrU1YAx2ucotdQm9ZMy2hNW8bRYOUjfnjdAjD6cic7V3D9EwjNpM/640?wx_fmt=other&from=appmsg)

① 系统割裂：活动系统、算法变更、产品发版，各躺在各自领域里，系统割裂，彼此不通气，AI 根本看不见这些内部动作。在过去人类怎么解决？一大杀招就是开会！什么日会、周会、同步会、讨论会，其实最大的作用在于交换与对齐信息。

② 隐形知识：更麻烦的是，大量信号压根没进过系统。散在会议里、钉钉的对话里、走廊的两句闲聊里，真实世界发生的变化，数字世界里的 AI 感知不到，就成了一块块隐形的知识，连人自己都未必理得清。

>
>
> 「可能解法是什么？IM 是组织里用得最勤的地方，钉钉、飞书里存着大量组织记忆，还天然带着身份和权限，是最该被 AI 读到的一手信息源。字节把飞书放到豆包底下，我猜就是看中了这一点，一个围绕 AI 而生的 IM？再往下，得有一个开放的企业知识库，把散着的组织记忆持续攒起来、归好档、理成结构。」
>
>

* 卡校验（Harness · 心里有尺）

![](https://mmbiz.qpic.cn/sz_mmbiz/kN3t5R6pdz4savYU80IfWeqAibGVN5PnKpOp6lq5y7lf5l5VmNT80mT96jfyQuUwM9FRHZaib8rpPpJQZGYqPoKmDpN4HJYoQu93a8ZaRKH9Y/640?wx_fmt=other&from=appmsg)

这里比较好约束，让 AI 留下推断证据、走完 check list 就行。不要硬做成模板和代码实现，一来很难维护，二来 Agent 会变笨。实测在上下文不爆炸的情况下，90% 以上会执行，能很有效地防止无中生有的幻觉。

### 5.5 产出目标 ###

这一步交出的，是一个下钻到位、排除了混淆、**站得住追问的归因结论**——而不是一句听起来很有道理的猜测。

这一步是 Agent 最容易翻车、也最见功力的地方。能查数的工具很多，敢说「证据不足，我先不下结论」的很少。

第六步：【B 分析判断 → A 业务结论】翻译成业务语言，产出判断与业务动作建议

### 6.1 难点是什么？ ###

绝大多数分析在精彩绝伦的掌声之后，听的人心里都会冒出一句：所以呢，我该干嘛？

就像你听完一堆理财分析，最后还是得追一句——买哪个，买多少，现在卖吗。

一种是只描述、不敢下结论；另一种是 AI 张口就来：「某某活动有效，可以加大补贴力度。」可预算从哪来、长尾商家能不能承接，一概不考虑。

再往回一步想，我们一开始要回答的那个业务问题是什么？

>
>
> 「美食行业最近怎么样，这个月的目标有没有风险？」
>
>

分析只是过程，最后要交出的是判断和动作。敢下结论、能给出靠谱建议的，才叫好分析师。

### 6.2 人怎么做到的？ ###

归因清楚了，最后一步是把它翻成老板能直接拍板的话。

翻这句话得靠什么？靠对业务的底子——盘子多大，本季度目标是什么，手里能动用的资源到哪，这条建议最后落到谁头上，有哪些绕不开的现实约束。所以说来说去，还是那句：有没有业务 sense。

说句实话，分析方法和算法，绝大多数没大学高数难，复杂的也不过是调包加微调。真正拉开分析质量差距的，就是这份业务 sense。

### 6.3 Agent 该怎么做？ ###

AI 是没有责任感的。它可以给出一份看着很专业的建议，但它不会为这个建议担责。方向押错了、团队折腾一圈没结果，最后扛的还是那个拍板的人。

此外，在真实世界中，一个建议从判断，到共识，到方案，到执行，再到回收，中间跨周期、跨部门传导。小团队或者小 OPC 还能端到端跑完，规模化的大组织里，Agent 要给出一个能落地的完美方案，非常难。

所以我们对 AI 的定位是：**识别信号，提供建议，作参考和辅助，不替人拍板**。

![](https://mmbiz.qpic.cn/sz_mmbiz/kN3t5R6pdz7e8Yceb1MSV15alib2iaGwaApdxq1IicoqUsYsIfhaIjUCWa1V3tU5EwJLVicfZiapedz8CN6SEwaO7ZsI50rVFhiak3QAtsfIbOSBs/640?wx_fmt=other&from=appmsg)

在这条边界内，AI 能补的其实不少：

* 把 归因 翻成 决策语言 ：别只甩一句掉了 2.1pp，要有论据、有因果链、有判断。

* 建议带约束 ：分档、分动作——干预、观察、验证，每条备注 Owner 。

* 标置信度 ：证据足就说结论，证据不足就明写「先不下结论」。这一条是 AI 最难、也最见诚意的地方。

* 要给方案就给 可选项 ：A 方案加大投放，预计……；B 方案先做核销保障，预计……让人可拍板，而不是替人拍板。

真正得留给人的是这几件：拍板担责、跨周期落地、组织共识、资源调配、执行回收。这几样短期内 AI 都替不了。

### 6.4 Agent 需要建设什么？ ###

现在 AI Native 这个词很火，但在数据分析这件事上，端到端真的很难跑通。卡住的地方常常不是技术，而是信任怎么建立、人和 Agent 怎么重新分工。

所以落地的时候我们建议先挑场景，优先挑这三种：

1.反馈快的 ： 一次小活动、一个小实验，几天就能验出 Agent 判断得准不准。对了就加码，错了改起来也不心疼。

2.能落到一个团队、一个小目标上的 ： 别一上来就搞大盘 GMV 分析 、总收入分析，这种题分析完了也没人能接着做动作，最后只剩一份没人看的报告。

3.以前做不到、有了 AI 才做得到的 ： 老活套个 AI 加速，天花板一眼就看到了；真正值得投的是增量，比如外部信号捕捉、话题挖掘这类过去人力铺不开的事。

很多分析做到最后，往往变成了“报信号”。AI盛行的年代，每个群里都有机器人每天报各种信息，但我们不妨回头想想，真正看的有几条？（这是一个灵魂拷问）

### 6.5 产出目标 ###

到这里，升维三步走完。当初电梯里那句「美食行业最近怎么样、目标有没有风险」，才算被完整回答了一次。

06

展望：大幕才刚拉开

写到这里，大概已经倒吸一口凉气：六步，步步是坑；每一步还要补齐 Context、Function、Harness、Loop；再叠上「可靠性连乘」那把达摩克利斯之剑。这么难，AI 智能分析是不是没戏了？

恰恰相反。

回头看看，我们翻来覆去只在讲一个词：翻译。

降维是把业务语言翻成机器听得懂的查询，

升维是把冰冷的数字翻回带着判断的业务语言。

六步、四模块、所有的坑，本质上都是同一件事：**让翻译不失真**。

过去二十年，数据流不动、沉在仓库里变成成本账单，卡点从来不是算力、不是存储，而是翻译这道工序太贵、太慢、太依赖人。

而今天，人类第一次造出了一台天生就通晓这两种语言的机器。

所以真正的问题，从来不是 LLM 行不行，而是会不会用它。LLM 给了我们前所未有的翻译原力；CFHL——**补上知识、配上手脚、立好尺子、拴上缰绳**，就是把这股原力驯服成一个靠谱的过程。

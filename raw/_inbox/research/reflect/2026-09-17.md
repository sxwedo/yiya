## 二、核心脉络与模式涌现 (Emergent Themes)

本周期摄入内容从早期的概念探讨全面收敛至**大厂生产级架构落地的攻坚战**，涌现出四个极具穿透力的工程范式：

### 1. 从 Prompt Loop 到 Harness 控制面与组织摩擦治理

- **核心洞见**：
  单点编码（Coding）提效已迅速逼近边际效益递减点。业界头部实践（腾讯、阿里、货拉拉）共识：**模型只负责发 `tool_use`，外围工程框架（Harness）负责掌控全局状态、断言与权限。**
- **技术机制与演变**：
  - **Harness 成为核心中枢**：区分模型思考与外围执行。模型产出结构化动作意向，外围 Harness 执行环境隔离、参数校验、会话滑动窗口管理及三层 Hash 验签；
  - **组织摩擦公式**：货拉拉千人研发实战总结出 $\text{组织效率} = \frac{T_{\text{价值创造}}}{T_{\text{价值创造}} + T_{\text{组织摩擦}}}$。AI 极度压缩了编码时间，但需求澄清、环境联调、跨组依赖的等待摩擦未变，使得整体交付周期（P85）依然停留在三个迭代以上；
  - **安全与执行解耦**：自然语言红线（Prompt 约束）在生产中彻底失效，必须演进为运行时硬隔离、白名单动作目录及独立副 Agent 审计防幻觉。
- **涉及词条/原料**：
  `[生产级垂类 Agent](<../../../../domains/agents/concepts/production-vertical-agent.md>)`、`[组织摩擦](<../../../../domains/engineering/concepts/organizational-friction.md>)`、`[Harness 运行时层](<../../../../domains/agents/concepts/harness-runtime-layer.md>)`。

### 2. 经验记忆的工业化提炼（Session → Trajectory → Experience）

- **核心洞见**：
  「把所有历史聊天塞给模型」或者「纯文本切片向量检索」已被证明既浪费 Token 又引入历史幻觉。记忆系统正式步入**分级生命周期的结构化提取时代**。
- **技术机制与演变**：
  - **三阶演变闭环**：以字节跳动 `OpenViking` 与阿里云 `AgentLoop` 为代表，任务执行产生 **Session**（单次上下文）；校验结果对齐后归档为 **Trajectory**（目标-路径-结局）；最后跨会话蒸馏成 **Experience**（可迁移的方法、前置条件、避坑规则）；
  - **防御性反哺应用**：在线任务召回经验时，严格核对环境前置约束，仅注入执行指导原则，严禁把历史任务的具体数值越权带入当前上下文，真正践行「历史不等于记忆」。
- **涉及词条/原料**：
  `[OpenViking](<../../../../domains/agents/entities/openviking.md>)`、`[AgentLoop](<../../../../domains/agents/entities/agentloop.md>)`、`[四层 Agent 记忆](<../../../../domains/agents/concepts/four-layer-agent-memory.md>)`、`[历史不等于记忆](<../../../../domains/agents/concepts/history-vs-memory.md>)`。

### 3. Data Agent 的「去 LLM 化执行」与业务本体论（Ontology）回归

- **核心洞见**：
  「自然语言直出 SQL 并执行」在企业复杂数据环境下是确定性的事故源。企业级取数与数仓智能体必须在 LLM 与底层数据库之间横插一层**确定性语义中介层（MQL / Semantic Layer）**。
- **技术机制与演变**：
  - **三层彻底解耦**：
    1. **LLM 意图解析层**：仅将用户自然语言解析为业务语义稿（包含业务实体、指标名、维度限定），绝不接触具体库表；
    2. **零 LLM 确定性引擎**：根据语义稿编译生成安全合规的物理 SQL，执行只读护栏、租户隔离与查询成本估算；
    3. **业务本体底座（Business Ontology）**：基于 DDD/OOD 思想构建业务对象、状态流转与指标口径映射表；
  - 数据工程的职责重心从写 ETL 脚本全面上移为「业务本体定义与语义层校验」。
- **涉及词条/原料**：
  `[Data Agent 落地](<../../../../domains/engineering/concepts/data-agent-landing.md>)`、`[业务 Ontology](<../../../../domains/engineering/concepts/business-ontology.md>)`、`[Text2Semantic2SQL](<../../../../domains/engineering/concepts/text2semantic2sql.md>)`、`[数仓分层](<../../../../domains/engineering/concepts/warehouse-layering.md>)`。

### 4. Vibe Coding 的精准语义约束（设计与工程词典）

- **核心洞见**：
  设计与前端体验无法通过含糊的感性词（「酷炫」「高级感」「自然」）交付给 Agent。必须将设计直觉转化为严密的枚举与受控 Skill。
- **技术机制与演变**：
  - **动效参数化**：将微交互拆解为触发、物理曲线、贝塞尔缓动、CSS 关键帧（入场、悬停、微反馈、页面平移）；
  - **去 AI 味规则固化**：将排版直角、负空间节奏、字体层次与去套路化的文案提炼为设计约束 Skill（如 Lieflat），使生成式前端从模板化收敛到具备工业级审美的直觉系统。
- **涉及词条/原料**：
  `[Vibe Coding 网页动效词典](<../../../../domains/design/concepts/vibe-coding-motion-lexicon.md>)`、`[Lieflat Less AI Tone](<../../../../domains/design/entities/lieflat-less-ai-tone.md>)`、`[AI 生图判断](<../../../../domains/design/concepts/ai-image-judgment.md>)`。

## 三、认知差与边界演化 (Epistemic Delta)

对比过去积累的常识体系，本周新摄入的知识完成了以下关键认知迭代：

- **新认知立项**：
  - **组织摩擦放大定律**：工具提效如果局限在单点编码，整体交付瓶颈会迅速滑向上下游的排期与对齐。评估 AI 价值不能只看代码生成行数或 FPY，要看带签名的合入存活率与需求流转等待时间；
  - **记忆降噪的物理前置核对**：召回的历史经验卡若无独立前置适用断言，反而会成为新的系统级幻觉源；
  - **双令牌数据访问控制**：自然语言查数必须拆分为「语义确认令牌」与「物理查询令牌」，没有语义确认严禁下发真实计算。
- **旧认知修正/推翻**：
  - **推翻「单 Agent Loop 是最终解」**：长复杂任务中，单 Agent 必然随上下文膨胀与循环步数增加而发生注意力退化与幻觉堆叠；工程实践正全面向「固定工序流水线 + 专职子 Agent + 独立判定门（Evidence Gate）」迁移；
  - **推翻「Prompt 负向禁令即可保安全」**：诸如「请勿修改非必要字段」「不要擅自退款」等自然语言提示在生产流量下失效率极高；必须以运行时工具白名单与数据权限系统构筑物理防线。
- **适用边界明晰**：
  - **垂类 Agent 适用区**：优先在「高频、低资损风险、规则相对可穷举、能单点闭环」的场景落地（如内部只读查数、工单初筛、代码补齐）；高情绪、多方利益博弈场景必须保留人工确认网关。

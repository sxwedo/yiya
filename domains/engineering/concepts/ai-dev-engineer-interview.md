# Definition

**AI 开发工程师面试**（Miles Ma，面试官视角）：岗位不是「会调模型」，是把模型做成**能用、能维护的软件**——接业务接口和流程，处理错误，检查结果，让真人用上。客服回信、改代码助手都一样：生成只是中间一步。Agent / 大模型应用 / 部分算法开发，文里都算这一岗。

公司算的账：你创造的价值能不能盖住用人成本；基础岗先看靠不靠谱（问清、提前说做不完、提交前自检）；高级岗看额外判断（把需求问清楚、挡住一次错选）；管理再看带人把事做完。只报「成功上线」不够，要拆出**本人的判断和贡献**。

简历分两套：

- **基础岗**：用经历证明能持续交付、能处理卡住的事、能把旧知识带到新接口。项目写成「给谁解决什么 → 自己哪一段 → 做过什么决定 → 怎样验证」。工具清单没有信息；超时发生在哪一层、重复请求怎么判，必须能追问下去。
- **高级岗**：写条件、决定、结果、哪些办法可迁移。数字要交代口径（响应时间还是吞吐；准确率从多少到多少）。管理岗还要写谁后来能独立接。

开场先问专家还是管理。标签不如过去的行为：专家追最近挖深的技术问题；管理追合作卡住时你有没有处理。介绍先给入口，别从大学一路讲到每家公司。

专家线（写进简历的部分要能讲为什么、试过什么、怎么验证）：

1. 编程与服务站得住：长任务不能堵在一个请求里；重启后状态、已完成步骤、是否可重入。查错数据时要想到身份、缓存键、权限，不只会写 SQL。
2. 模型调用：token ≠ 汉字；上下文放得下 ≠ 模型用得对；结构化输出仍要验字段和业务含义；连续格式失败要有限重试并显式失败，不能把坏结果当正常数据。换模型先收口调用层。
3. 业务状态和模型上下文分开。订单是否提交以业务系统为准，不能靠聊天摘要。压缩后重复执行，先查真实任务状态。长期记忆要有范围和更正，不是把聊天全存下来。
4. 工具最容易露馅：超时先查是否已生效，用请求标记或幂等；无权限不要盲重试；「Agent 说完成了」查真实产物。停条件（时间/轮次/费用/风险/人工）要事先有。
5. 评测先定义完成，再覆盖缺信息、工具失败、越权、长任务。别只报平均分。换模型后总分升、关键任务变差，要能停那一类，不能被简单题盖住。
6. 部署：KV cache 让「单次很快」推不到多人长输入；量化要实测任务有没有变差。先拆排队 / TTFT / 生成 / 工具，再决定加机器。
7. 微调按岗加深。损失下降、业务没涨，先查数据与目标、评测覆盖、过拟合、推理配置。基础岗可以说清哪些只学过、哪些做过。

管理线分项目（目标、限制、第一批功能怎么选、接口不到怎么改范围）和团队（延期先查目标/能力/依赖/检查点，不是每次替写；真实分歧怎么拍板）。项目叙事准备三层：做了什么；为什么、有哪些替代；条件变了怎么办。再准备一个扎实决定和一个没做完的问题。代码主要由 AI 写也可以，但要能改条件（比如加上用户隔离）。

转型：围着一个目标岗做小而完整的项目（模拟邮件+订单就能考上下文、工具、权限、状态），按「跑起来 → 异常 → 评测与部署」加条件，不要先买什么都讲的课。

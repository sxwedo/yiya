# Definition

**在线记忆流水线**（货拉拉）把「消息 → 当前可用的记忆」拆成四段，故意**不**在消息一到时立刻抽：

1. **任务调度** — 不判断值不值得记，只把一段完整、可执行、可恢复的会话交给提取。消息先落成待处理任务；同步可等到写入完成，也可先返回后台做。同一会话聚合成一次提取（会话完整性），5 万 Token 上限卡住单次大小，并发限制卡住慢模型。健康检查回收失活执行器；提取失败延迟重试；长期待处理会被捞起；超过上限保留失败原因，禁止无声丢失。
2. **记忆提取** — 不要整段会话，也不要揉成一段摘要。产物是**脱离原文仍可独立理解的候选事实**。输入三类：本轮+近期会话（理解）、近期事实+召回的已有事实（判新增/补充/冲突/重复）、观测日期与关注范围（边界）。用户消息里的稳定背景、偏好、计划、条件可提；AI 消息只有可追溯、后续仍依赖的约定/结果才提，且必须标来源。问候、空评、一次性情绪不进长期。七类检查维度（偏好、个人信息、计划、接单条件、健康、职业、其他）防止只抓显眼话题。质量：有明确依据、保留变化语境（不能只留「现在在西城区」）、专名与条件不泛化、相对时间换成观测日、来源可分用户/AI。去重删的是副本，不是再次出现的证据。
3. **记忆管理** — 候选事实仍是散点。补四层结构：事实主记录（库）与检索索引分开，更新/删除/审计只走库再同步索引；实体链接用人物/地点/机构/时间作多对多入口；用户画像只维护反复需要的稳定字段（称呼、语言、职业…），一次性经历不升格；关联记忆回答「理解这条还应带上哪些」，概念标签只留主题线索。两者都不是实体链接。
4. **混合检索** — 保存求全，读取求焦。三路召回：向量定候选范围，全文（关键词）和实体只给这些候选加信号，不把三路简单并集以免噪声。两阶段排序：粗排把语义/BM25/实体分校准融合；精排判断是否真正贴合问题，必要时展开关联/画像。交给模型的是有限集合，不是增长中的历史。

离线侧（轻度/深度/REM 睡眠）整理重复、过时与冲突——本页不写。得物的「请求前并行加载 + 会话后异步沉淀」是**热路径怎么读、写路径怎么卸**，见 [异步记忆沉淀](./async-memory-precipitation.md)。本页专精**提取单元与召回结构**。
